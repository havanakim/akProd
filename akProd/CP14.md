# CP_mono · 헤더별 수치 등록 / 저장자료 조회

> 2026-11-17: 신규 사진 저장을 제거했습니다. 사진은 OCR에만 사용하며 사진 없이 수동 등록도 가능합니다. 기존 DB는 scripts/cp-values-only.sql 적용이 필요합니다. 배포 안내: CP_VALUES_ONLY.md.


메인 메뉴의 등록 → CP_mono에서 촬영·입력하고, 조회 → CP_mono에서 저장자료 목록을 바로 연다.
메인 메뉴에서 들어간 조회 화면에는 메뉴로 돌아가는 버튼을 제공한다.

현재 메뉴/테이블명은 CP_mono이다. cp-menu-schema.sql은 초기 AKSMART 이름과 이전 하이픈 이름 모두에서
언더라인 이름으로 변경할 수 있다. DB에 실제 반영하려면 대상 DB에서 스크립트를 실행해야 한다.

## 저장 항목

화면에 인쇄된 헤더 코드를 저장 키로 사용한다. 각 행은 왼쪽에서 오른쪽으로 5→4→3→2→1이다.
사용자가 '헤더 값으로 인식'하도록 지정한 범위에 맞춰 별도 보압 압력 HP도 포함한다.

| 화면 | 항목 | 저장 헤더 | 개수 |
|---|---|---|---|
| 사출 및 보압 | 사출 압력 | IP5, IP4, IP3, IP2, IP1 | 5 |
| 사출 및 보압 | 사출 속도 | IV5, IV4, IV3, IV2, IV1 | 5 |
| 사출 및 보압 | 보압 압력 | HP5, HP4, HP3, HP2, HP1 | 5 |
| 사출 및 보압 | 보압 시간 | HT5, HT4, HT3, HT2, HT1 | 5 |
| 계량, 배압 및 흘림방지 | 계량 위치 | S5, S4, S3, S2, S1 | 5 |
| 계량, 배압 및 흘림방지 | 계량 속도 | RV5, RV4, RV3, RV2, RV1 | 5 |
| 계량, 배압 및 흘림방지 | 배압 | BP5, BP4, BP3, BP2, BP1 | 5 |

사출 및 보압 20개, 계량·배압·흘림방지 15개를 각각 별도로 저장하며 0/0.0/000은 정상적인 숫자 0으로 처리한다. 인식하지 못한 값을 0으로 채우지 않는다.
사출 위치 IF5~IF1 및 S0, 그래프/현재값/하단 상태/지연시간/흘림방지 설정 등은 대상에서 제외한다.
사진에 보이는 예시 수치를 앱의 기본값으로 고정하지 않는다.

## 등록

1. 메인 메뉴 CP_mono를 연다.
2. 화면 종류를 선택하고 해당 화면 사진을 촬영하거나 선택한다.
3. 사진은 선택 사항이며 서버에는 수치만 저장한다. 같은 화면의 보완 사진은 최대 5장까지 추가한다. 다른 화면은 새 등록으로 별도 저장한다.
4. IP/IV/HP/HT/S/RV/BP 헤더와 각 헤더 바로 아래의 숫자를 자동 연결한다. 한국어/영문 원본, 흑백 대비 보정, 황색 문자 마스크를 비교한다.
5. 선택 화면의 20개 또는 15개 입력값을 확인한다. 추가 사진과 기존 값이 다르면 기존 값을 덮어쓰지 않고 확인 표시를 남긴다.
6. 필요한 항목은 헤더 선택 → 숫자 영역 드래그 → '선택 항목만 다시 읽기', 또는 직접 입력한다.
7. 사진과 값을 확인했다는 체크 후 서버 등록을 누른다.

헤더가 인식되지 않으면 위치를 추측해 다른 열의 숫자를 대입하지 않는다. 빈칸이 있으면 저장을 막고 헤더를 안내한다.
사진이 너무 작거나 반사/기울기가 심하면 헤더와 소수점 인식에 실패할 수 있으므로 선택한 표가 크게 보이도록 촬영한다.
촬영/불러오기 시각은 기기 현지시각이다. 모니터에 표시된 날짜/시각을 대신 저장하는 방식은 아니다.

## 저장 후 조회

저장 성공 후 저장 상세 화면이 자동으로 열린다. 상세 화면은 입력 폼의 값을 복사하는 것이 아니라 DB에 커밋된 자료를 다시 조회한다.
목록과 상세에 화면 종류를 표시하고 해당 화면 항목만 조회한다. 기존 통합자료는 두 화면을 그대로 표시한다. 각 행에 헤더 5개와 값 5개를 같은 순서로 표시하며 저장 사진도 볼 수 있다.

CP_mono 등록 화면의 '저장자료 조회'에서는 로그인 작업자 본인의 자료를 촬영/불러오기 현지시각 기간으로 조회한다.
기본 기간은 최근 7일이며 시작일/종료일을 yyyy-MM-dd로 바꿀 수 있다. 20건씩 이전/다음 페이지를 제공한다.
목록에서 자료를 선택하면 상세 헤더별 값과 사진을 조회한다. 이 화면은 조회 전용이다.

## DB 적용

현재 local.properties의 DB_NAME에 해당하는 DB에 scripts/cp-menu-schema.sql을 1회 적용한다. 앱에서 테이블을 자동 생성하지 않는다.

- [dbo].[CP_mono]: 요청 ID, 설비 CP14, 작업자, 현지 촬영/불러오기 시각, 서버 UTC 등록시각, 항목 JSON, 내용 해시, 사진 수.
- [dbo].[CP_mono_PHOTO]: 요청 ID, 사진 순서, 각 사진의 현지 불러오기 시각, JPEG, 인식 결과.

신규 등록은 수치만 저장하고 PHOTO_COUNT=0으로 기록한다. 사진 테이블에는 쓰지 않는다. 같은 요청과 같은 내용으로 재시도하면 중복 등록하지 않는다.
전송 직전의 입력과 사진 경로를 기기에 보관하며 결과를 확인하지 못한 건은 값을 잠그고 동일 요청으로 재확인한다.
DB 계정에는 두 테이블 SELECT/INSERT 권한이 필요하다. 기존 CP3/PB5 데이터와는 별도 테이블이다.

예시 조회:

```sql
SELECT REQUEST_ID, USER_ID, CAPTURED_AT, PHOTO_COUNT,
       JSON_VALUE(VALUES_JSON,'$.FIELDS.IP5') AS IP5,
       JSON_VALUE(VALUES_JSON,'$.FIELDS.HT1') AS HT1,
       JSON_VALUE(VALUES_JSON,'$.FIELDS.S5') AS S5,
       JSON_VALUE(VALUES_JSON,'$.FIELDS.BP1') AS BP1
FROM [dbo].[CP_mono]
ORDER BY CAPTURED_AT DESC;
```

## 검증

헤더/숫자 좌표 자료를 사용한 순수 JVM 검증 20건 통과: 두 화면 35개 항목 연결, 분리된 헤더,
표 이동, 헤더 문자 혼동, 그래프 범례와 표 헤더 구분, 빈칸과 0 구분, 누락 셀의 다른 열 오배정 방지, 제외 항목 배제.
Kotlin 신규 4개 파일 구문 검사 및 저장/조회 계층의 연결 스텁 기반 JVM 컴파일을 수행했다.
실제 사진 ML Kit 인식률, 실기기 UI, 실제 SQL Server 저장/조회 검증을 대신하는 결과는 아니다.

APK 빌드도 시도했으나 plugins.gradle.org DNS 조회 실패로 foojay-resolver Gradle 의존성을 받지 못해
Android 컴파일 전에 중단되었다. Android Studio에서 의존성을 받을 수 있는 환경의 Sync/Build와 실기기 확인이 필요하다.


## 메뉴/테이블 개편 및 비트맵 0 보정
기존 데이터가 있는 DB에는 scripts/cp-menu-schema.sql을 실행한다.
기존 AKSMART_CP3_CAPTURE/PHOTO와 AKSMART_CP14_CAPTURE/PHOTO를 각각
[dbo].[CP_Colored]/[dbo].[CP_Colored_PHOTO], [dbo].[CP_mono]/[dbo].[CP_mono_PHOTO]로 이름만 변경한다.
기존 자료를 삭제하지 않는다. 두 이름이 이미 함께 존재하면 자동 병합하지 않고 전체 작업을 중단한다.
신규 DB에서는 같은 스크립트가 새 이름의 테이블을 생성한다.
저장 후에는 DB 자료를 다시 읽어 상세 화면을 열며 기간별 내 저장자료 및 저장 사진을 조회할 수 있다.
8비트 스타일의 사선 0은 원본 글자 이미지의 내부 빈 공간과 기울기를 검사해 보정한다.
실제 8/9를 문자열로 일괄 치환하지 않는다. 보정된 항목에는 사진 비교 표시를 남긴다.
합성 글꼴 테스트 결과는 실제 사진 OCR 정확도를 대신하지 않는다.

## 앞자리/소수부 0이 8로 인식될 때
1. 예를 들어 실제 010.0이 810.0으로 읽힌 항목을 선택한다.
2. 사진에서 숫자 전체(010.0)만 드래그해 선택한다. 테두리와 단위는 제외한다.
3. '0 인식 보정 학습'을 누르고 사진의 정답을 앞자리 0까지 010.0처럼 그대로 입력한다.
4. '학습 후 다시 읽기'를 누른다. 0 글꼴이 설비별로 기기에 저장되고 같은 사진을 다시 분석한다.
5. 다른 글꼴이거나 영역을 잘못 배웠으면 '0 보정 학습 초기화' 후 다시 학습한다.

000.0/010.0/050.0의 글자 수와 소수점 위치를 유지해 학습한다. 학습 후 8/9로 인식된 글자만
원본 글꼴과 비교하며 정상 8의 위아래 구멍과 9의 열린 좌하단을 보호한다.
같은 사진에서 잘못 읽었던 값은 형태 근거가 확인된 경우 재입력하며 다른 수동 입력값은 보존한다.
학습은 ML Kit 모델 전체의 재학습이 아니라 해당 모니터 0 글자 표본을 이용한 보정이다.
합성 이미지 10건 검증은 실제 사진의 정확도 보증이 아니므로 실기기에서 결과를 확인한다.
## 화면별 저장 적용
기존 DB에는 scripts/cp-mono-single-screen.sql을 실행하여 사진 수 제한을 0~5장으로 변경한다. 기존 자료는 유지한다. 신규 레코드의 VALUES_JSON에 SCREEN_TYPE으로 화면 종류를 저장한다.
