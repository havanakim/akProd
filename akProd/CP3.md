# CP_Colored · 사출/보압 수치 등록

> 2026-11-17: 신규 사진 저장을 제거했습니다. 사진은 OCR에만 사용하며 사진 없이 수동 등록도 가능합니다. 기존 DB는 scripts/cp-values-only.sql 적용이 필요합니다. 배포 안내: CP_VALUES_ONLY.md.


메인 메뉴는 등록/조회 카테고리로 구성한다. 등록 → CP_Colored는 촬영·입력 화면,
조회 → CP_Colored는 저장자료 목록 화면으로 바로 연결된다. 조회에서 메뉴로 돌아갈 수 있다.

현재 메뉴/테이블명은 CP_Colored이다. cp-menu-schema.sql은 초기 AKSMART 이름과 이전 하이픈 이름 모두에서
언더라인 이름으로 변경할 수 있다. DB에 실제 반영하려면 대상 DB에서 스크립트를 실행해야 한다.

akProd 메인 메뉴의 CP_Colored에서 사진에 보이는 설정 표를 읽어 저장한다.
PB 5호기와 CP_mono 메뉴를 함께 제공한다.

## 입력 항목 (총 29개)

| 사진의 단계 | 저장 항목 |
|---|---|
| 보압 3, 보압 2, 보압 1 | 각각 압력(kgf/cm²), 속도(%), 시간(sec) |
| 사출 5, 사출 4, 사출 3, 사출 2, 사출 1 | 각각 압력(kgf/cm²), 속도(%), 시간(sec), 위치(mm) |

키는 HOLD_3_PRESSURE, HOLD_3_SPEED, HOLD_3_TIME … INJECT_1_POSITION 형태다.
메뉴는 테이블(CP_Colored / CP_mono)로 구분한다. MACHINE_CODE와 VALUES_JSON의 "MACHINE"에는 등록 화면에서 고른 사출기 호기(C01~C16)를 넣는다.
호기 선택 기능 이전 자료와 그 이전에 만든 미확인 임시저장 건은 메뉴 코드(CP3/CP14)가 들어 있다.
사진 속 수치를 기본값으로 고정하지 않는다. 0은 유효한 측정값이다.
첨부 사진의 보압 3/2 속도 칸처럼 실제로 표시가 없는 경우만 해당 항목의 '사진에서 표시 없음'을 체크한다.
표시 없음은 NOT_DISPLAYED 배열로 저장하며 숫자 0과 구분한다. 다른 누락 항목은 확인·입력해야 저장할 수 있다.
모델명, Robot, 현재 압력, 밸브 지연시간, 경보, 하단 상태는 저장 수치에 포함하지 않는다.

## 사용

1. CP_Colored를 선택하고 전체 사진 또는 좌측 확대 사진을 추가한다.
2. 필요한 경우 우측 확대 사진도 추가한다. 최대 5장까지 같은 건에 모을 수 있다.
3. 같은 시점의 설정 사진만 함께 사용한다. 추가 사진의 값이 기존 값과 다르면 덮어쓰지 않고 확인 표시를 남긴다.
4. 자동 인식 결과를 사진과 비교한다. 단계 제목이 잘렸거나 반사로 글자가 사라지면 해당 열을 확정하지 않는다.
5. 필요하면 항목 선택 → 사진에서 숫자 부분을 드래그 → '선택 항목만 다시 읽기', 또는 값을 직접 입력한다.
6. 표시 없는 보압 3/2 속도를 확인하고 전체 확인에 체크한 뒤 서버 등록을 누른다.

인식은 단계 제목(보압 3/2/1, 사출 5/4/3/2/1)을 먼저 찾고, 각 단계의 열과 압력/속도/시간/위치 행을 연결한다.
한국어 원본 OCR과 영문/숫자 대비 보정 OCR 결과를 비교한다. 고정 사진 좌표나 예시 숫자를 사용하지 않는다.
근접 사진을 합쳐 부족한 열을 보충할 수 있지만 서로 다른 시점의 값을 자동으로 구별하지는 못한다.
촬영/불러오기 시각은 기기 현지시각이며 첫 사진 시각과 각 사진별 시각을 저장한다.

## DB 적용

앱에서 DB를 자동 생성하지 않는다. 현재 local.properties의 DB_NAME에 해당하는 테스트 DB에서
[scripts/cp-menu-schema.sql](scripts/cp-menu-schema.sql)을 1회 적용한다.

- [dbo].[CP_Colored]: 요청 ID, 설비, 작업자, 현지 촬영시각, 서버 UTC 등록시각, 항목 JSON, 내용 해시, 사진 수.
- [dbo].[CP_Colored_PHOTO]: 요청 ID, 사진 순서, 각 불러오기 현지시각, JPEG, 항목별 OCR 결과.

DB 계정에는 두 테이블 SELECT/INSERT 권한이 필요하다. 기존 업무 테이블/프로시저는 변경하지 않는다.
신규 등록은 수치만 저장하고 PHOTO_COUNT=0으로 기록한다. 사진 테이블에는 쓰지 않는다. 같은 요청 ID/내용으로 재시도하면 중복 등록하지 않는다.
내용이 다르면 충돌 오류로 거절한다. 등록 결과가 불확실하면 입력을 잠그고 같은 요청 재확인을 사용한다.
전송 직전의 입력과 사진 경로를 기기에 보관하여 메뉴에서 나갔다 돌아와도 재확인할 수 있다.
등록이 끝나면 '새 등록 시작'으로 다음 건을 작성한다.

예시 조회:

```sql
SELECT REQUEST_ID, MACHINE_CODE, USER_ID, CAPTURED_AT, PHOTO_COUNT,
       JSON_VALUE(VALUES_JSON,'$.FIELDS.HOLD_1_PRESSURE') AS HOLD_1_PRESSURE,
       JSON_VALUE(VALUES_JSON,'$.FIELDS.INJECT_1_POSITION') AS INJECT_1_POSITION
FROM [dbo].[CP_Colored]
ORDER BY REGISTERED_AT DESC;
```

## 메뉴/테이블 개편 및 비트맵 0 보정
기존 데이터가 있는 DB에는 scripts/cp-menu-schema.sql을 실행한다.
기존 AKSMART_CP3_CAPTURE/PHOTO와 AKSMART_CP14_CAPTURE/PHOTO를 각각
[dbo].[CP_Colored]/[dbo].[CP_Colored_PHOTO], [dbo].[CP_mono]/[dbo].[CP_mono_PHOTO]로 이름만 변경한다.
기존 자료를 삭제하지 않는다. 두 이름이 이미 함께 존재하면 자동 병합하지 않고 전체 작업을 중단한다.
신규 DB에서는 같은 스크립트가 새 이름의 테이블을 생성한다.
저장 후에는 DB 자료를 다시 읽어 상세 화면을 열며 기간별 내 저장자료 및 저장 사진을 조회할 수 있다.
8비트 스타일의 사선 0은 원본 글자 이미지의 내부 빈 공간과 기울기를 검사해 보정한다.
실제 8/9를 문자열로 일괄 치환하지 않는다. 보정된 항목에는 사진 비교 표시를 남긴다.
합성 글꼴 테스트 결과는 실제 사진 OCR 정확도를 대신하지 않는다.

## 앞자리/소수부 0이 8로 인식될 때
1. 예를 들어 실제 010.0이 810.0으로 읽힌 항목을 선택한다.
2. 사진에서 숫자 전체(010.0)만 드래그해 선택한다. 테두리와 단위는 제외한다.
3. '0 인식 보정 학습'을 누르고 사진의 정답을 앞자리 0까지 010.0처럼 그대로 입력한다.
4. '학습 후 다시 읽기'를 누른다. 0 글꼴이 설비별로 기기에 저장되고 같은 사진을 다시 분석한다.
5. 다른 글꼴이거나 영역을 잘못 배웠으면 '0 보정 학습 초기화' 후 다시 학습한다.

000.0/010.0/050.0의 글자 수와 소수점 위치를 유지해 학습한다. 학습 후 8/9로 인식된 글자만
원본 글꼴과 비교하며 정상 8의 위아래 구멍과 9의 열린 좌하단을 보호한다.
같은 사진에서 잘못 읽었던 값은 형태 근거가 확인된 경우 재입력하며 다른 수동 입력값은 보존한다.
학습은 ML Kit 모델 전체의 재학습이 아니라 해당 모니터 0 글자 표본을 이용한 보정이다.
합성 이미지 10건 검증은 실제 사진의 정확도 보증이 아니므로 실기기에서 결과를 확인한다.
