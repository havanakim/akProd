# LCD 숫자 OCR 전처리

## 적용 범위

CP14·CP3 사진 추가 시 전체 사진 자동 인식과 선택 영역 재인식에 적용한다.
공정관리일지 OCR은 별도 처리 흐름이며 이번 적용 대상이 아니다.

기존 원본·명암 조정 인식(CP14는 노란 글자 마스크 포함)을 먼저 실행한다.
이어 `LcdOcrPipeline`이 OpenCV 추가 인식을 순차 실행한다.

1. 전체 사진은 축소본에서 기존 MonitorDetector로 화면 ROI를 찾는다. 검출 실패 시 전체 사진을 사용한다.
   선택 재인식은 사용자가 지정한 숫자 ROI를 사용한다.
2. 회색조 → CLAHE(clipLimit 2.0, 8×8 타일).
3. CLAHE 영상, Otsu 이진 영상, Otsu+방향별 closing, 적응형 이진화+방향별 closing의 네 경로를 인식한다.
4. 이진 영상 테두리로 밝고 어두운 배경을 구분해 흰 획에 closing을 수행한다.
   가로·세로 closing은 각각 원본 이진 마스크에서 수행하고 OR로 합친다.
   커널은 3 또는 5픽셀이며, 전체 사진과 선택 영역에 서로 다른 크기 비율을 사용한다.
5. ML Kit에는 검은 글자·흰 배경 이진 영상을 전달한다. CLAHE 경로는 회색조를 그대로 사용한다.
6. 전체 사진 CLAHE 경로는 한국어 엔진으로 제목·행 이름도 인식한다. 나머지는 일반 문자 엔진을 사용한다.
7. ROI 자르기·확대로 바뀐 OCR 좌표를 원본 사진의 정규화 좌표로 복원한 뒤 기존 표 매핑에 전달한다.

전체 사진 자동 인식도 기존 헤더·행·열 근거가 있어야 값을 배정한다.
헤더가 끝내 인식되지 않거나 사진이 기울어진 경우에는 영역 조정과 선택 재인식이 필요할 수 있다.
이번 구현은 원근 보정이나 독립적인 7세그먼트 숫자 인식기를 포함하지 않는다.

## 0/8 검증과 후보 처리

`SevenSegmentVerifier`는 closing 이전 원본 사진 픽셀을 Otsu 이진화해 검사한다.
열 투영으로 끊어진 세그먼트를 같은 숫자로 묶고, 숫자 개수가 OCR 문자열과 일치할 때만 진행한다.
바깥 여섯 획과 위·아래 내부 빈 공간의 형태가 맞는 경우 중앙 획 점유율로 0/8을 판정한다.
불명확한 중앙 획, 겹친 숫자, 사선 0, 균일 영상, 자리 수 불일치는 보정을 보류한다.
확실한 세그먼트 판정은 기존 글꼴 학습 보정보다 우선하며, 적용 불가 시 기존 보정을 유지한다.
소수점과 앞자리 0은 형태 검증 과정에서 보존한다. 저장 값의 숫자 정규화는 기존 표 파서를 따른다.

인식 경로별 숫자 후보가 다르면 자동 입력을 보류하고 후보를 항목 오류 메시지에 표시한다.
기존 입력은 남겨두며, 새 값이 하나로 합의되어도 불명확한 0/8은 사진 확인 안내를 표시한다.
확인할 항목의 사진 ROI는 후보 충돌 시에도 선택할 수 있다.

## 빌드와 자원 관리

- `app/build.gradle.kts`: 공식 `org.opencv:opencv:4.13.0` AAR 추가.
- `settings.gradle.kts`: OpenCV 그룹은 Google 저장소 조회에서 제외하고 Maven Central로 해석.
- OpenCV 초기화 실패 시 기존 OCR 결과를 사용하고 안내한다.
- 전처리는 백그라운드에서 수행하고, 경로별 영상은 순차 생성·해제한다.
- ML Kit 작업 완료 전에는 입력 Bitmap을 해제하지 않는다. 취소된 화면에는 결과를 적용하지 않는다.
- Mat·커널과 임시 Bitmap을 해제하고, 추가 인식 영상의 최대 변 길이를 1800픽셀로 제한한다.
- 공식 AAR 네이티브 라이브러리로 APK 용량이 증가한다. 단말 ABI별 배포 최적화는 별도 검토 대상이다.

검증 명령(Windows):

```powershell
./gradlew.bat :app:assembleDebug :app:testDebugUnitTest --no-daemon --no-configuration-cache --console=plain
```

## 2026-11-17 검증 결과

- Android debug APK 빌드 성공.
- 기본 configuration cache 설정으로도 빌드·검증 성공 및 캐시 저장 확인.
- JUnit 16개 통과: 기존 OCR 회귀검증 9개, 신규 세그먼트 형태 검증 7개.
- 신규 검증: 0/8 교정, 실제 8 유지, 밝고 어두운 배경, 끊어진 바깥 획, 소수점,
  불완전 중앙 획 보류, 자리 수 불일치, 균일 영상, 사선 0 보류, 앞자리 0 보존.
- APK: `app/build/outputs/apk/debug/app-debug.apk`.
- 범용 debug APK 약 190.2 MiB. OpenCV 네이티브 라이브러리 arm64-v8a·armeabi-v7a·x86·x86_64 포함 확인.
- 실기기 OpenCV 로딩·ML Kit 실행과 실제 사진 정확도·처리 시간은 미검증.
  JVM 검증은 형태 판정 로직을 검증하며 Android OpenCV 전처리를 실행하지 않는다.

실기기 확인 시 같은 LCD 사진의 정상 0·8, 획 끊김, 반사광, 어두운 배경, 작은 소수점,
앞자리 0을 비교한다. `010.0 → 810.0`, `050.0 → 850.8` 사례를 포함하고,
충돌 안내·선택 재인식·화면 이탈·연속 사진 추가의 동작 및 처리 시간을 확인한다.
커널 크기와 이진화 설정은 이 결과에 따라 조정한다.
