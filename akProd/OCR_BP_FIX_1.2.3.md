# 배압 수집 수정 1.2.3

BP5~BP1이 읽혔어도 전체 사진 OCR에서 나온 다른 숫자 후보가 남으면 최종 입력을 모두 보류하던 문제를 수정했다.

- 배압 칸의 확대 원본·CLAHE·Otsu에서 유일하게 우세한 2회 이상의 일치 결과를 사용한다. 전체 사진의 약한 후보 때문에 이 일치를 버리지 않는다.
- 0과 8/9 후보가 충돌하면 단순 다수결로 8/9를 선택하지 않는다. 원본 글자 검증 결과가 있으면 우선하고, 없으면 확인 대상으로 남긴다.
- 어두운 화면의 0 내부 무늬를 보존하도록 임계값을 실제 원본 밝기 범위에 맞춘다.
- 20을 기본값으로 채우지 않는다. 다른 수치, 0, 인식 누락, 동률에 대한 검사도 포함한다.
- 디버그 빌드는 앱 내부 last-mono-ocr.json에 후보·확대 인식 횟수·최종 입력값을 기록한다. 사진이나 작업자 정보는 이 진단 파일에 넣지 않는다.

DB 구조 및 기존 저장값은 변경하지 않는다. 새 등록에서 사진을 다시 불러와 확인한다.

최종 단말 검증: 재연결 후 설치 버전 1.2.3을 확인했다. 20261116_090348(가까운 사진), 20261116_090252(먼 사진)의 BP5~BP1 모두 최종 20으로 판정해 10/10개가 원본과 일치했다. 전체 사진 진단 결과는 build/ocr-comparison/mono-full-photo-v1.2.3-final.json에 보관한다. 회귀 검사 42개 통과. 이 시험은 DB 등록을 수행하지 않았다.
