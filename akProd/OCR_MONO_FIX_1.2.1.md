# mono 사진 인식 수정 1.2.1

보고된 증상: 보압 000/000.0 누락, 075→875, 020.0→820.0, 계량 RV1 25.0→25.8, S5/S3/S2/S1 및 BP5/BP4/BP1 누락.

수정 내용:
- 실제 사진에서 확인된 $5/84/$3/82/81 및 BU1 헤더를 S/RV 항목으로 해석.
- 최초 헤더 위치를 유지하고 다음 행의 헤더가 숫자 영역에 들어오지 않도록 확대 영역 조정.
- 사진 불러오기 시 4000픽셀 원본의 강제 절반 축소를 방지하고 로컬 사진 보존 한도 확대.
- 원본 밝기를 유지한 자리별 0/8/9 검사 및 여러 임계값의 일치 확인.
- 전체 OCR이 숫자를 놓쳐도 실제 모든 글자가 0으로 검증되는 경우에만 0 수집. 빈칸을 0으로 채우지 않음.
- 누락/충돌/불확실 항목의 칸별 확대 OCR. 일반 확대·CLAHE·Otsu 결과의 일치로 0/8/9 후보 충돌 해소.
- 구별되지 않은 8/9는 자동 입력하지 않고 확인 표시.

단말의 첨부 전체 사진 진단에서 HP5~HP2의 000 원본 검증, S5=010.0, S3=100.0, S2=130.0, S1=148.0, BP5/BP4/BP1=20을 확인했다. 별도 사진 영역 검사에서 875→075 및 820.0→020.0을 확인했다. 진단은 DB에 쓰지 않는다.

1.2.2 추가: 연결된 노란 선택 배경을 분리하고 반전 숫자를 정상화한 뒤 자리별 모양을 검증한다. 20261116_090348 및 20261116_090252의 RV1 사진 영역에서 25.8→25.0 보정을 회귀 검사로 확인한다. 실제 8/9는 보존하도록 검사한다. 모든 사진의 모든 필드가 항상 자동 수집되는 것을 보장하지 않으며, 불확실 값은 자동 입력하지 않는다.

시험용 원본 사진/정답은 androidTest에만 있으며 배포 앱에는 포함되지 않는다. 수치 정답을 앱에 고정 입력하지 않는다.
